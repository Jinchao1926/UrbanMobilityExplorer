# iOS 应用 - 城市交通探索者 作业要求

## 项目目标
构建一款用于探索城市交通站点（如共享单车、共享电动车站点）的 iOS 应用。用户可浏览可用站点、查看站点详情，并收藏常用站点。

本次作业旨在评估高级 iOS 开发能力：架构设计、UI 状态管理、数据处理、持久化存储、错误处理、可维护性及实际方案权衡。

---

## 时间要求
请在 48 小时内提交解决方案，实际开发时长预计为 **6-8 小时**（非 48 小时持续开发）。  
优先保证实现可靠、清晰的核心功能，而非堆砌大量非必要特性。

---

## 技术要求
- 仅支持 iOS 平台，使用 Swift 开发
- 优先使用 SwiftUI，UIKit 也可接受
- 最低部署目标：iOS 16
- 合适场景下使用 `async/await`
- 应用必须可构建、可运行，包含完整可用的 UI
- 禁止提交硬编码的密钥、API Key 或 Token

---

## 数据来源
使用真实的城市交通站点数据，可选择以下方式之一：真实开放 API、公共数据集、示例 JSON、Mock 服务器或本地数据提供方。项目需保证在无网络环境下仍可正常评审。

可选数据源：
- CityBikes API
- GBFS 公共数据
- OpenStreetMap/Nominatim
- Open-Meteo（可选天气相关数据增强）
- 其他公共交通/位置 API

---

## 核心功能（必须实现）
### 1. 站点列表
展示包含有效可用信息的站点列表，需支持以下常见用户场景：
- 加载状态
- 空数据/错误状态
- 刷新
- 搜索
- 排序或筛选（根据场景选择实现）

### 2. 站点详情
提供选中站点的详情页面，包含站点位置、当前可用状态等关键信息。

### 3. 收藏功能
支持用户保存并快速访问收藏的站点。收藏数据需跨应用启动持久化存储，且在无法加载最新数据时仍可正常使用。
